Find the shortest walk across campus

PSU PathFinder is a campus navigation website for Pangasinan State University – Urdaneta Campus. It shows the actual campus map with its buildings, possible entrances, original walkways and alternative walking paths, and finds the shortest measured walking route between any two of the 14 official locations with Dijkstra's algorithm.

Choose where you are and where you need to go. The route is drawn along the campus walkways, never through a building, together with the total distance and an estimated walking time.

        About the project

        PSU PathFinder: A Campus Navigation and Shortest-Path Optimization System

        PSU PathFinder is a web-based campus navigation system for Pangasinan State University – Urdaneta Campus. It is the final project of Group 3 in Data Structures and Algorithms (Computer Engineering) and applies graphs, a min-heap priority queue and Dijkstra's shortest-path algorithm to a real navigation problem on our own campus.

        Purpose

        PSU PathFinder was developed to give students and visitors an accessible way to locate buildings and facilities within Pangasinan State University – Urdaneta Campus. Freshmen, transferees and other people who are unfamiliar with the campus layout often have to ask for directions or spend extra time looking for a classroom, laboratory or office.

        The website provides a digital representation of the campus buildings, their possible entrances, the original campus walkways and the available alternative walking paths. Through graph data structures and Dijkstra's algorithm it determines the shortest available route from the walking distances the group measured. A min-heap priority queue (Python heapq) selects the next closest location during the search, and dictionaries give fast look-up of locations, distances and previous stops. SQLite stores the campus information, walkway data, route measurements and the navigation history.

        PSU PathFinder does not use live GPS tracking. Its navigation is based on predefined campus data that the proponents prepared and validated.

        Main objectives

        1. Represent the campus digitally with its actual map, official building locations, original walkways and alternative walking paths.
        2. Implement a weighted graph and Dijkstra's algorithm in Python to find the shortest available route between two locations.
        3. Use a min-heap priority queue and dictionary look-up for efficient route calculation and location search.
        4. Build a responsive website with Flask, HTML, CSS, JavaScript and SQLite that shows campus information, routes and distances.
        5. Publish the website through GitHub and Render so it can be opened online.

        • Weighted graph stored as an adjacency list (dict of vertex → edges)
        • Min-heap priority queue – Python heapq
        • Hash tables – dict for distances, predecessors and name/ID look-up
        • Set – vertices whose shortest distance is final

        How the navigation system works

        1. Campus data. The 14 official locations, 17 possible entrances, the walkway network and the building footprints are traced on the original campus map and the annotated maps, then stored in SQLite. Purple lines on the latest annotated map are original campus walkways; orange lines are alternative walking paths. The two are never merged.
        2. Measured distances. The building-to-building walking distances come from the group's Excel workbook (91 pairs). A missing or "N/A" value stays empty; no distance is guessed.
        3. Shortest distance. Dijkstra's algorithm runs on the building graph weighted by those measured metres. This gives the total distance and the order of stops.
        4. Route line. A second Dijkstra search on the traced walkway graph chooses which walkway line to draw for each part of the route. Every line is checked against all building footprints and is rejected if it would pass through a building.
        5. Result. Flask returns the result as JSON; the page only draws what the server calculated and saves the search in the route history.

        The new orange Quadrangle path is drawn over Engineering Bldg. 1, so it is shown on the map but is not used for routing until the corridor is confirmed walkable and its length is measured.
